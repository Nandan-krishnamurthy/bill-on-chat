0. Why Two Phases

The original spec couples two very different kinds of work: the product (agent reasoning, GST
correctness, the data model, PDF generation) and the transport (WhatsApp delivery through
OpenClaw, webhooks, media handling, message idempotency). The transport
is plumbing. The
product is the hard, valuable part.

Splitting the build means we ship and validate the entire billing brain against a simple web chat
UI first, with zero transport friction and fast iteration. WhatsApp then becomes a thin adapter
layer bolted onto an already
-
working system. The /chat endpoin

2. Two Operating Modes

The same agents and the same data serve two completely different audiences, and the agent's
job changes depending on who it is talking to. This is the central concept of Project Beta. There
are two personas: Owner Mode and Customer Mode.

Owner Mode

the agent is the shopkeeper's back
-
office assistant. It helps the owner
run

the
business: check stock, see who owes money, record payments, create invoices, send
reminders, and pull sales and GST reports. Full trust, full access.

the agent is a salesperson acting
on the owner's behalf
, talking to the
owner's end customers. Its job is to sell: answer product questions, quote prices, check
availability, and capture an order as a draft. It is not running the business and must never

14. Definition of Done

Phase 1 (web chat)

Owner Mode

using only the web chat (persona set to Owner), a shopkeeper can:

Create / select a business (name, GSTIN, state).

Add 5 customers and 10 products.

Create an invoice with 3 line items and receive a GST
-
compliant PDF in the chat.

Record a full and a partial payment.

Get a sales summary and a GSTR
-
1 summary for the month.

Customer Mode

with the persona set to Customer, an end customer can:

Ask whether a product is available and what it costs (and see nothing else).

Place a draft order, which the owner then sees and confirms into a real invoice.

Not

reach any other customer's data, dues, reports, or exact stock

verified by the
boundary tests.

Phase 2 (WhatsApp)

Everything in Phase 1, plus, using only WhatsApp:

Onboard a new business from a first
-
time WhatsApp number (owner).

A customer messaging the shared customer entry point is served in Customer Mode
automatically.

Receive the invoice PDF as a WhatsApp attachment.

Generate an E
-
Invoice and get back an IRN; generate an E
-
Way Bill when required.

Send a payment reminder to a customer on WhatsApp.

Drive a flow with a voice note and with mixed
-
language text.
